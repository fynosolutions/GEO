# Listing quality — Issue #18

This module isolates the issue-specific export policy from legacy listing snapshots and menu/history contracts. `public.ts` provides four-state classification, numeric ratings, evidence-gated confirmed absence, six-attempt provider retries and a conservative whole-batch budget ledger. Original provider data and rating_raw stay intact. No search result is assumed manually reviewed; errors and empty datasets alone never prove absence. Confirmed absence requires a successfully collected search result plus an explicit reviewed identity check and search URL.

Retries wait three seconds, initial attempt plus five retries. An uncertain Actor start or unconfirmed termination stops for reconciliation instead of blindly duplicating paid work. Budget exhaustion must be reported as incomplete acceptance, never as successful stability. These cases require a documented issue discussion if they prevent the mandatory retry acceptance. Review IDs/author work is outside this module.

`npm run collect:listing-quality` prints a no-cost estimate. `npm run collect:listing-quality -- --live` stages three consecutive captures per store before moving to the next store in .local/issue18, with a conservative $10 aggregate reservation and $0.05 default per-Actor cap ($0.50 for Google Maps and SERP discovery, matching their published minimum caps). Reservation exhaustion halts incomplete acceptance. The final fresh batch completed all eighteen store-round files; the third-round results and reviewed differences are delivered in samples/step1-listing. Earlier diagnostic/resumed captures remain separate private evidence.

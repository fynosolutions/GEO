# F1 实施基线

2026-10-19，经 grilling 访谈确认。本文记录已批准的实现选择，不代表功能已经完成；实际验证见 F1_VALIDATION.md。

同日按用户要求调整为美国餐馆与英文工作站。技术栈不变；当前 f1.v2、地区字段、英文保存和旧资料兼容约定见 US_MARKET_BASELINE.md。

## 范围和交付

完整实现 F1 PRD 的 8 个工作包和 AC01–AC33。最早联调里程碑是基础建档、持久化、稳定 ID、固定版本读取及可调用公开接口，不据此宣称完整 F1 完成。A1、B1、报告仅保留原占位。

## 技术

Windows 本机、浏览器访问，服务仅监听 127.0.0.1。TypeScript、Next.js App Router、Tailwind CSS、按需 shadcn/ui 控件；SQLite、Drizzle 和版本化 SQL 迁移。npm 管理并锁定依赖。Vitest 验证业务和持久化，Playwright 验证主要页面流程。

页面交互在 app，商家规则和公开类型在 modules/merchant，数据库和文件适配在 infrastructure。其他模块仅通过 merchant/public.ts 使用商家能力。HTTP 是页面适配，不能替代模块公开服务。

## 数据和历史

品牌、门店、资料分组及各类重复明细结构化持久化，类型与字段目录统一。当前表用于编辑；每次实际变化在同一事务中提交当前值、不可变资料快照和变更记录。品牌更新同时推进关联门店版本。历史冻结品牌、证据和素材元数据及关联，附件内容不可变。无变化不产生版本，旧版本提交明确冲突。

沿用 f1.v2 的状态、金额、分页、错误、三种读取投影，以及版本/适用日期/时区规则。11 类资料均有公开读取入口。内部元数据不进入 publishable 白名单。

## 界面和运维

桌面优先、浅色、画面简单、信息清晰，便于连续录入。快速建档后按组补充，核实和公开范围独立处理。Windows 启动脚本，提供安装、迁移、升级说明。

附件复制到可配置的数据目录，用 ID 引用，默认单文件 50 MB。默认运行数据在 .local/geobase，备份在 .local/backups，均不提交；GEOBASE_DATA_DIR 和 GEOBASE_BACKUP_DIR 可指向其他本地磁盘，勿将活动数据库放入网络共享或同步文件夹。

每天首次启动、开放编辑前完整备份，保留最近 7 份成功自动备份，不清理手动备份。失败提示重试或明确选择继续。备份含数据库、附件、清单和校验值；恢复先完整校验和备份当前数据，再由操作者确认整体替换，失败原数据可用。

容量设计目标：数百门店、数万明细、上万份图片/PDF，不是硬限制。实际性能与附件体积有关，未实测的容量不得宣称达标。

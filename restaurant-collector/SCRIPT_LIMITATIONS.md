# 为什么第一版采用半自动采集

目标是取得可追溯、属于同一分店的餐厅资料，供后续与商家本地事实比对。自动脚本仍保留名称和地址模糊匹配、候选排序与页面访问能力；当前推荐先用日常 Chrome 的本地扩展收集资料，验证字段质量，再推进批量检索和比对集成。

## 已观察到的情况

| 场景 | 本项目观察 | 对实现的影响 |
| --- | --- | --- |
| Google Maps 独立浏览器 | 真实门店页面可读取名称、地址、电话、官网，但显示有限视图 | 页面能打开不代表所有栏目可采集；不能将缺失字段判为商家未填写 |
| Google 登录 | 用户在独立自动化窗口登录受阻，并看到 `--no-sandbox` 提示 | 已显式启用 Chromium 沙箱；去掉该标记不保证自动化浏览器可登录 |
| Yelp | 访问返回 HTTP 403，响应含 DataDome / captcha-delivery 验证线索 | 当前访问拒绝，无法验收 Yelp 完整采集；不能仅凭此归因于网络“不安全” |
| Google 动态栏目 | 选中标签、网址和异步内容可能不同步；Menu 内也有 Overview | 需要结合选中标签、网址与人工覆盖；About 和菜单必须分开存储 |
| 菜单 DOM | 分类导航、订位提示与菜品文字共处一个内容区域 | 需过滤页面控件，保留原文和待复核标记，不能把第一个价格前的所有文字当菜品 |

这些是开发期间的具体观察，不表示每次运行或每家餐厅都会出现。Codex 浏览器连接超时属于另一条工具连接链路，不能据此证明 Google/Yelp 在阻止页面采集。

## 脚本检索难在哪里

**登录会话和平台访问控制。** Playwright 默认启动独立浏览器，不使用个人 Chrome 的登录状态。Google 官方说明，可能拒绝受软件自动化控制的浏览器登录。因此，开启项目持久档案或启用沙箱都不能保证可登录。[Google 账号浏览器支持说明](https://support.google.com/accounts/answer/7675428)

**自动流量识别。** Google Search 官方公开了异常自动流量与验证码处理机制；这是 Search 的说明，不能推定为 Maps 的完整检测规则或具体阈值。现有 Maps 有限视图和 Yelp 403 证据不足以判断用户网络是否不安全，也不能证明降低请求频率一定能解除限制。[Google Search 异常流量说明](https://support.google.com/websearch/answer/86640)

**候选召回和分店确认。** 名称或门牌号有少量错误时，匹配算法可以对已返回候选排序，但无法匹配平台没有返回的候选。同品牌多店或只有城市级位置时，需要用户补充地址或人工确认，不能自动选中一个看起来相似的门店。

**页面是动态界面。** 点击、滚动、栏目展开与内容加载都有状态。稳定取得基本字段后，仍需要单独处理 About、菜单分类和图片卡片。DOM 变化会使选择器失效，单纯增加等待时间不能解决错误归类或文字污染。

**字段含义不同。** About 常是设施、服务和氛围，而非介绍段落；Gemini 评论摘要不是商家自述；普通菜单也不是招牌菜清单。完整数据需要同时检查访问状态、字段来源和语义，不能只检查 HTTP 成功或 JSON 非空。

## 当前实现和使用边界

- 独立脚本串行导航、限制候选数和访问频率；遇到 429 停止，对验证和同意页面提供人工处理入口，保留截图与 HTML 诊断。
- 扩展由用户在日常 Chrome 中搜索并确认门店、打开 About 和各菜单子分类，再点击采集。它解决当前页面的资料提取，不提供自动检索、自动滚动或批量遍历。
- 扩展仅在当前页读取 DOM 和显式选中文字，记录留在本机；不读取 Cookie、密码、浏览历史，不自动登录或绕过验证码。
- 0.2.2 将 About 属性与菜单分开，过滤已知订位控件文案，保存菜名、说明、原价文字及原始观察。未知结构、图片菜单和新的页面文案仍需人工复核。
- 更新扩展后，已有菜单会在汇总和导出时重新解析；历史快照及其指纹保持不变。缺失字段为 `null / not_collected`，不代表该字段在平台不存在。

## 下一步路线

1. 用半自动扩展校准不同门店的栏目和菜单样式，记录准确率与漏采情况，再接入商家本地描述比对。
2. 需要批量取得名称、地址、电话等基础信息时，评估 Places API 的 Text Search 与 Place Details，通过 FieldMask 请求所需字段；API 仍需要费用、字段覆盖和使用规则设计，不能预设其提供完整菜单或商家认证招牌菜。[Place Details 官方说明](https://developers.google.com/maps/documentation/places/web-service/place-details)
3. 需要核对商家自己管理的资料时，另行评估商家授权接口；Yelp 数据来源独立评估。网页采集、官方 API 和商家提供的事实都应保留来源与观察时间。

扩展逐步操作见 [使用说明](extensions/google-maps-collector/README.md)，脚本参数与访问状态见 [Google Maps 脚本说明](GOOGLE_MAPS.md)。

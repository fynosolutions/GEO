# GEO Google Maps 资料采集扩展

这是项目自带的本地 Chrome 扩展，尚未发布到 Chrome Web Store。推荐它作为第一版半自动采集入口：用户在日常 Chrome 正常登录和浏览，扩展在点击时读取当前门店，复用项目字段抽取器，不启动自动化浏览器。

## 安装

1. 在 Chrome 地址栏打开 `chrome://extensions/`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择克隆仓库中的 `restaurant-collector/extensions/google-maps-collector` 文件夹（文件夹内应直接包含 `manifest.json`）。
5. 在 Chrome 工具栏的扩展列表中固定“GEO Google Maps 资料采集”。

不需要运行 Node、启动服务器或重启已登录的 Chrome。这里加载的是本项目源码，不是重新安装 Codex 的 Browser 扩展。Windows 同事选择克隆仓库内的对应文件夹即可。

Mac 文件选择窗口中，可按 `⌘⇧G`，输入自己电脑上的扩展完整目录，再按回车选择。加载后如果修改扩展代码，需要在扩展管理页点击刷新。

## 采集一家门店

1. 在日常 Chrome 中正常打开 Google Maps，搜索餐厅并人工确认分店。
2. 进入“概览”，打开扩展，保留“自动识别当前栏目”，点击“采集当前页”。第一份记录必须包含名称与地址。
3. 关闭弹窗，在页面点击 About；再次打开扩展会显示识别结果。设施、服务、停车等按属性组保存；实际餐厅介绍单独保存在简介，不把整个 About 当成一段简介。
4. 点击 Menu，再分别点击 Lunch menu、Drink、Soup、Sauce 等子分类。打开扩展查看识别结果及分类名后采集。未自动取得分类名时，在“菜单子分类”中填写页面上的实际标签。菜单按分类保存菜名、说明、原价文字和原始文本；不同子分类是补充记录，不视为互相冲突。
5. 若页面内容可见但未自动识别：关闭弹窗，选中菜单文字或 About 内容，打开扩展，保留“按当前栏目保存”，点击“保存选中文字”。菜单可以包含多道菜的名称、说明和价格，不再要求每行都是菜名。只选择特色/热门菜名时，才选择相应用途。页面仅提供菜单图片时，本版不做 OCR。
6. 检查预览，点击“导出 JSON”。通常保存至 Chrome 下载目录，实际位置由浏览器设置决定。
7. 另一家门店需先导出，再点击“新建采集”。扩展检测到另一个门店标识时会拒绝混入。

不要把评论里的顾客看法当作商家简介；普通菜单菜名不自动等于招牌菜。Google 页面未展示的信息仍可能无法取得，扩展不改变平台权限或数据覆盖。

## 接入后续脚本

当前扩展版本为 **0.2.2**；导出文件使用 `google-maps.manual.v2`，保留一个门店、基础字段、分类菜单 menu、设施服务 attributes、页面快照、来源时间与内容指纹。后续比对模块可读取 `platforms.google_maps.fields`；未取得字段为 null / not_collected。

在终端进入仓库的 `restaurant-collector` 目录，导入并生成可读报告：

```sh
node restaurant_collector/import-manual.mjs --input ~/Downloads/google-maps-实际文件名.json
```

脚本兼容 v1/v2，重新校验快照指纹和门店身份。v2 使用键排序的规范化 JSON 计算指纹，避免 Chrome 存储时改变键顺序导致误报。内容指纹只用于检查意外修改，不证明网页真实性或商家确认。名称、地址、联系方式变化保留在 conflicts；不同简介片段保留在 descriptionVariants，人工明确选择的简介优先展示。不同菜单分类及设施标签不产生简介冲突。

旧 v1 中误存进 description 的菜单文本与 About 属性，导入时按原页面栏目重新分类；原快照保持不变。旧记录没有保存的菜单子分类不能凭空恢复，显示“未标注分类”，需要补采标签。Google 链接含区域及门店多个标识时使用最后的门店标识，升级会从旧快照重建它。

## 权限与数据

仅使用 activeTab、scripting、storage。打开扩展时识别当前栏目，点击采集才保存记录。没有后台常驻服务、所有网站访问权限、远程上传或自动登录逻辑。只处理 google.com/maps 页面。记录保存在 Chrome 扩展本地存储，关闭弹窗后仍保留；不会读 Cookie、密码或浏览历史。不会修改 Google Maps 内容、解决验证码或自动点击菜单。采集字段和导出来自页面 DOM 及显式选中文字，不包含整页截图或 HTML。

## 开发与验证

修改主项目抽取器后，在 `restaurant-collector` 目录运行 `pnpm build:extension`，然后在 Chrome 扩展页点击此扩展的刷新按钮。它会更新扩展内的 extract.mjs 副本，避免与自动采集脚本分叉。

规则测试覆盖同店跨栏目合并、另一分店拒绝、未知字段和不同表述保存。浏览器测试使用本地页面，不能代替用户已登录 Google Maps 的真实验收。

升级后在 `chrome://extensions/` 找到本扩展，点击刷新，关闭旧弹窗再重新打开。旧采集记录保留；无需卸载或新建采集才能使用修正后的汇总逻辑。

## 常见问题

- **About 是否属于菜单？** 不属于。About 的设施服务保存在 `fields.attributes`，餐厅介绍保存在 `fields.description`，分类菜单保存在 `fields.menu`。About 页不显示菜单子分类输入框；选中的 About 标签优先于尚未更新的网址。
- **菜单内部的 Overview 是什么？** 是 Menu 的子栏目，保留在菜单中，不能据此跳回门店概览。
- **订位广告被识别成菜名？** 0.2.2 过滤完整匹配的订位提示、按钮文字和菜单导航。已有记录在预览及导出时按新规则重新解析；原快照与指纹不变。遇到新广告文案，检查 `parseStatus: needs_review`，或选中仅含菜品的文字再采集。
- **看到了其他分类，但导出只有 Lunch Menu？** 分类标签只证明页面有入口；需要逐个打开并采集其菜品。当前扩展不会自动点击、滚动或遍历全部分类。
- **About 有内容，简介却为空？** 设施与服务不是商家介绍。页面没有实际介绍段落时保留未知；Gemini 评论摘要也不自动作为商家简介。
- **Popular 菜品在页面上可见却没取得？** 目前只覆盖部分明确的热门菜栏目 DOM；概览中的图片卡片仍可能漏采。可以选中实际热门菜名，选择“仅特色/热门菜名”补采。普通菜单不自动升格为招牌菜。
- **菜单只有图片？** 本版不做 OCR；没有 DOM 菜名或可选文字时不能自动结构化。
- **保存失败或内容不完整？** 先检查是否为 `google.com/maps` 门店详情页、是否载入并展开目标内容。存储空间不足时先导出，再新建采集。

完整访问限制与选择半自动流程的原因见 [脚本检索限制说明](../../SCRIPT_LIMITATIONS.md)。扩展不会实现输入名称、位置后的自动模糊搜索：这个能力在独立脚本中；扩展由用户确认门店。

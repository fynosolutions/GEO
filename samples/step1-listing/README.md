## Output rules

- Non-booking rows add store, absence and search_url; Facebook also includes recommend_text. Easy Joy uses store `020`; the other five use the original names from the review task.
- rating is a number or null, rounded to one decimal precision. Recommendation percentages and unrated values do not become stars; rating_raw retains source evidence.
- Existing OpenTable/Resy facts and timestamps remain. KPOT's historical OpenTable rating=0 with zero reviews becomes null; its rating_raw stays unchanged. Booking platforms were not collected again or classified as absent.
- All rows were generated by code. The same final mapper re-exported all captures from saved provider results, including the previously omitted Uber Eats ratingValue; original captures were not edited.
- Actual cost and every remote run's terminal state were reconciled, including diagnostic and aborted runs, within the US$10 limit. Billing and account/Actor identifiers remain private local evidence.

The original Issue #12 workbook and manual-check sheets are historical records. They do not assert that the new third-round values match the older page captures.

## Offline verification

```sh
npm ci
npm run check
npm run build
npm run verify:listing-quality
BROWSER_CHANNEL=chrome npm test
```

The verifier needs no token, private inputs or network. It checks all eighteen files, presence/score invariants, booking fingerprints, explained differences and byte equality of round three with the final samples. It does not replace live source validation.

## Recollect and derive new results

Configure your own APIFY_TOKEN in .env. Follow backend/listing-quality/README.md to reconcile prior spending before any paid run. Do not start a second batch while live.lock exists.

```sh
npm run collect:listing-quality                # no-cost estimate
npm run collect:listing-quality -- --live
# If a capture halted, reconcile its remote states/cost before continuing:
npm run collect:listing-quality -- --live --resume .local/issue18/<halted-capture>
# Use one final mapping policy across all saved rounds:
node scripts/reexport-listing-quality.mjs .local/issue18/<complete-capture> .local/issue18/<derived-export>
# Review every difference against saved providers before promotion:
node scripts/promote-listing-quality.mjs .local/issue18/<reviewed-derived-export>
node scripts/promote-listing-quality.mjs .local/issue18/<reviewed-derived-export> --publish
node scripts/report-listing-quality.mjs .local/issue18/<complete-capture> .local/issue18/<reviewed-derived-export>
npm run verify:listing-quality
```

Exact source replay requires the ignored local captures, attempt logs and billing receipts. A new checkout can verify delivered samples offline; it cannot fabricate private source evidence. These commands are the Issue #18 acceptance path; ordinary UI and weekly snapshot schemas remain separate.
